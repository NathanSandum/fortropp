Show exact wording before writing user-facing docs or UI copy, and don't build a whole described plan because the user answered one question in it.

**Why:** on 2026-11-02 the user answered a proof question with "A, go ahead", and a docs page and a setup-dialog line got written from the surrounding plan. They were irritated and had both removed: the copy cluttered and confused, and how to talk to users depends on the feel of the whole product. They also reject needy or over-explaining phrasing, and often have a specific sentence in mind.

On 2026-11-08 they also set two rules for state messages: state the fact without presuming how it arose ("This website cannot be found", not "no longer exists"), and never tell the user what to do ("Choose another…") outside tutorial content.

**How to apply:** ask what "go ahead" covers when a plan has several parts. When wording is rejected and it's unclear which piece, ask which one. If unsure, leave copy out and defer it to the visual round. Related: [[feedback-discuss-product-decisions]].
